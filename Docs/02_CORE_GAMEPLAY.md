# Project 77 — Core Gameplay

## 1. Status

Core mechanic **не считается окончательно утверждённой**, пока не пройдёт быстрые прототипы и тесты на новых игроках.

**Текущая фаза:** Prototype 0.1. Полный active scope/DoD/out-of-scope описан в `28_PROTOTYPE_01_SPEC.md`.

Требования к любой механике:

- понять базовое правило ≤ 5–10 секунд;
- one-finger control;
- удобство на телефоне;
- сессия 30–90 секунд;
- сотни уровней могут создаваться системно;
- возможность новых rules/modifiers;
- отсутствие необходимости в сложной анимации для каждого уровня;
- естественные boosters;
- тематическая связь с исследованием, маршрутизацией, восстановлением и древними технологиями.

## 1.1 Prototype implementation rules

- Engine: Unity 6.3 LTS, C#, URP.
- Android is the first runtime target.
- Первые прототипы намеренно используют примитивы, placeholder UI и минимальные эффекты.
- Core puzzle оценивается отдельно от качества art.
- До выбора победившей механики не производить сотни уровней.
- После выбора механики собрать meta prototype: `Puzzle -> reward -> island action -> discovery -> next puzzle`.
- Prototype 0.1 завершается восстановлением генератора и обнаружением робота 77.

## 2. Prototype A — Energy Routing (основной кандидат)

### Rule

На небольшом поле находятся источники и приёмники энергии/сигнала. Игрок проводит маршруты так, чтобы соединить нужные точки и активировать систему.

Базовая версия:

- пары одинаковых узлов;
- пути не должны пересекаться;
- часть клеток блокирована;
- нужно заполнить/активировать критические участки.

### Почему подходит Project 77

Вместо абстрактных точек игрок «чинит»:

- генератор острова;
- электрическую сеть;
- маяк;
- дверь лаборатории;
- древний терминал;
- систему корабля;
- планетарный шлюз;
- сеть врат.

Одна механика естественно меняет визуальный смысл по мере раскрытия мира.

### Evolution modifiers

1. Blocked cells.
2. One-way gates.
3. Limited path length.
4. Moving node.
5. Timed pulse.
6. Splitter.
7. Teleporter pair.
8. Hazard cell.
9. Multi-stage board.
10. Hidden node revealed after first connection.

Не вводить новый modifier чаще, чем игрок освоил предыдущий.

### Boosters

- Hint — показывает один корректный фрагмент.
- Undo+ — откатывает несколько действий.
- Bridge — разрешает одно пересечение.
- Pulse — автоматически соединяет одну пару.

Boosters должны иметь бесплатные источники.

## 3. Prototype B — Expedition Paths

Игрок направляет несколько исследователей/дронов к целям на компактной карте. Их пути запускаются одновременно после планирования и не должны столкнуться.

Плюсы:

- визуально живее;
- можно связывать с персонажами;
- хорошие «aha moments».

Минусы:

- сложнее читается;
- требует больше анимации;
- сложнее процедурно валидировать уровни.

## 4. Prototype C — Signal Sequence

Игрок соединяет символы/узлы в заданной логической последовательности, одновременно соблюдая ограничения поля.

Плюсы:

- очень простой UX;
- отлично тематизируется как дешифровка.

Минусы:

- риск восприниматься как слишком абстрактная puzzle game;
- слабее связь с островной метой.

## 5. Prototype gate

До производства сотен уровней нужно сделать 3 небольших прототипа.

Для каждого:

- 15–20 тестовых уровней;
- первые 5 уровней без текста после первого tutorial gesture;
- 10+ внешних тестеров, не знающих правила заранее;
- записать completion time, retries, wrong gestures, субъективное желание сыграть ещё 5 уровней.

Core mechanic выбирается по данным, а не по красоте концепта.

## 6. Level structure

Уровень состоит из:

- board definition;
- objective;
- constraints;
- modifier set;
- target difficulty;
- reward tier;
- analytics metadata.

Контент должен храниться data-driven, чтобы level designers могли менять баланс без перекомпиляции логики.

## 7. Difficulty bands

- 1–10: onboarding/easy win.
- 11–30: закрепление.
- 31–60: первые комбинации.
- 61+: волнообразная сложность.

Не делать линейную кривую «каждый следующий сложнее».

Рекомендуемый pattern:

Easy → Medium → Medium → Hard → Easy → Medium → Hard → Reward/Story level.

## 8. Story integration

Не каждый puzzle должен изображать буквальную электрическую схему. Визуальный skin может меняться:

- расчистка троп;
- восстановление сети;
- настройка радио;
- дешифровка;
- маршрутизация дронов;
- запуск древнего устройства.

Но underlying rule должен оставаться узнаваемым.

## 9. Infinite/challenge mode

После открытия определённой главы игрок получает Challenge mode, чтобы core gameplay оставался доступным даже при ожидании story actions.

Это уменьшает необходимость искусственных energy walls.

## 10. Procedural assistance

Не делать полностью procedural levels без контроля качества.

Лучший вариант:

- генератор предлагает solvable candidates;
- automated solver проверяет решение и примерную сложность;
- дизайнер принимает/корректирует;
- production telemetry показывает фактическую сложность.

## 11. Core success criteria

Механика считается жизнеспособной, если новые игроки:

- понимают её почти без текста;
- регулярно получают ощущение «я сам догадался»;
- не путают управление с UI;
- готовы добровольно пройти ещё несколько уровней без сюжетной награды;
- не требуют постоянной смены механики, чтобы не скучать.
